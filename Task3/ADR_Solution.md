|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|
| :-: | :- | :- | :- |
|1|Новый клиент|Подача заявки на депозит через сайт|1. Клиент заходит на сайт банка<br>2. Просматривает список доступных депозитов с актуальными ставками<br>3. Заполняет заявку (ФИО, телефон, выбранный депозит)<br>4. Отправляет заявку<br>5. Получает подтверждение о принятии заявки|
|2|Менеджер кол-центра|Обработка заявки с сайта|1. Получает уведомление о новой заявке<br>2. Просматривает заявку в системе кол-центра<br>3. Звонит клиенту<br>4. Предлагает условия депозита (в том числе персонализированные)<br>5. Приглашает клиента в отделение для оформления|
|3|Существующий клиент|Подача заявки на депозит через интернет-банк|1. Клиент авторизуется в интернет-банке<br>2. Просматривает доступные депозиты с персонализированными ставками<br>3. Выбирает счет и указывает сумму депозита<br>4. Подтверждает заявку SMS-кодом<br>5. Получает подтверждение о создании заявки|
|4|Менеджер бэк-офиса депозитов|Обработка заявки из интернет-банка|1. Получает заявку на рассмотрение<br>2. Анализирует условия в АБС<br>3. Подтверждает или корректирует условия депозита<br>4. Отправляет решение клиенту|

#### Архитектурные решения

**1. Микросервисная архитектура для новых компонентов**
Для минимизации изменений в существующих системах создаем новый микросервис депозитов в составе интернет-банка. Это позволит:
- Избежать прямой интеграции с перегруженной АБС
- Обеспечить независимое масштабирование
- Сохранить стабильность существующих систем

**2. Асинхронная интеграция через Apache Kafka**
Использование брокера сообщений для передачи заявок между системами:
- Снижает нагрузку на АБС
- Обеспечивает надежность доставки заявок
- Позволяет обрабатывать пиковые нагрузки

**3. Кэширование ставок**
Внедрение кэша для хранения актуальных ставок по депозитам:
- Решает проблему медленной загрузки справочных данных
- Снижает количество запросов к АБС
- Обеспечивает быстрый отклик интерфейса

**4. API Gateway для централизованного управления**
Внедрение шлюза для:
- Единой точки входа в API
- Управления аутентификацией и авторизацией
- Мониторинга и логирования запросов

**5. Расширение АБС новыми модулями**
Добавление в АБС:
- Модуля управления ставками (замена Excel-файлов)
- Модуля обработки онлайн-заявок на депозиты

### **Альтернативы**

**1. Прямая интеграция с АБС**
Недостатки:
- Высокий риск перегрузки АБС
- Сложность масштабирования
- Зависимость от производительности Oracle DB

**2. Полная замена интернет-банка**
Недостатки:
- Высокие затраты и риски
- Длительные сроки разработки
- Потребность в миграции всех существующих функций

**3. Использование внешней платформы**
Недостатки:
- Дополнительные интеграции
- Зависимость от внешнего провайдера
- Сложности с соблюдением требований безопасности

### **Недостатки, ограничения, риски**

**Недостатки:**
- Усложнение архитектуры из-за добавления новых компонентов
- Необходимость поддержки нескольких технологических стеков
- Дополнительные точки отказа в системе

**Ограничения:**
- MVP предполагает ручную обработку заявок в бэк-офисе
- Новые клиенты все равно должны приходить в отделение для идентификации
- Зависимость от внешнего подрядчика для доработок ядра интернет-банка

**Риски:**
- Сложность синхронизации данных между системами
- Потребность в обучении команд новым технологиям (Kafka)
- Возможные проблемы производительности при росте нагрузки
- Необходимость миграции данных при переходе от Excel к системному управлению ставками
